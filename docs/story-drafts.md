# 第二课课前用户故事初稿

这些故事来自立项时的产品设想，供团队带进访谈核实。访谈后为保留的故事关联匿名证据，记录改写或舍弃理由，再由团队确定验收标准。

| 编号 | 作为用户，我希望…… | 我想解决的问题 |
| --- | --- | --- |
| S01 | 我想只录入今天准备试搭的三件衣物，之后再补齐衣橱。 | 临出门时也能试用，不必先整理全部衣物。 |
| S02 | 我想从一张照片或商品链接保存一件喜欢的衣服，稍后再确认具体款式。 | 走在路上时能先记住心动的那件。 |
| S03 | 买外套前，我想把它和我常穿的裤子、鞋放在一起看。 | 下单前能知道家里已有哪几件可以搭。 |
| S04 | 我想按实际要买的颜色、尺码查看几家店的报价和优惠条件。 | 避免被其他尺码或自己用不了的折扣误导。 |
| S05 | 看到报价时，我想知道上次核实的时间，并能打开原商品页。 | 付款前能自己确认库存和最终价格。 |
| S06 | 试穿后决定留下，我想把衣物和买前配好的那一身一起收进衣橱。 | 收货后不用重新拍照、录入或凭记忆找搭配。 |
| S07 | 办理退货后，我想让它退出可穿清单。 | 第二天的推荐里只出现我确实能穿的衣物。 |
| S08 | 我想带着今天的场合和想穿的一件单品，问衣橱其余几件怎么配。 | 得到一套能从自己衣柜里拿出来的搭配。 |
| S09 | 当一套衣服只有鞋不合适时，我想说明原因、只换鞋。 | 保留我已经选好的衣服，减少反复调整。 |
| S10 | 我想告诉助手哪一套我真的穿了、哪一件鞋走远路会磨脚。 | 下次遇到相似场合时，建议能考虑我的实际感受。 |

第二课讨论时同步询问可接受的等待时间、衣橱照片的访问与删除要求。候选非功能需求须由成员结合用户意见明确可验证的条件。
